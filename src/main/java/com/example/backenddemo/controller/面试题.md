Spring Boot 当前阶段面试题

1、为什么不直接在 Controller 里面写 new UserService()，而要让 Spring 注入？

如果直接 new UserService()，对象的创建和管理都由我们自己负责。
使用 Spring 的依赖注入后，UserService 由 Spring 统一创建和管理，
Controller 只需要使用它，代码耦合更低，也更方便维护和测试。


2、@Service 是干什么的？

@Service 用来标识业务层组件，由 Spring 管理。
业务逻辑主要放在 Service 层，这样 Controller 只负责接收请求，
业务变化时主要修改 Service，职责更加清晰，也降低了耦合。


3、Controller 和 Service 的区别是什么？

Controller 负责接收和返回请求，Service 负责处理具体的业务逻辑。

    Controller
    ↓
    接收 HTTP 请求
    ↓
    调用 Service
    ↓
    返回结果
    
    Service
    ↓
    处理业务逻辑
    ↓
    调用 Mapper
    ↓
    操作数据库


4、Mapper 是干什么的？

Mapper 主要负责数据访问，与数据库进行交互，
完成查询、插入、更新、删除等操作。

通常由 Service 调用 Mapper 来完成数据库操作。


5、为什么要把数据库操作放在 Mapper，而不是直接写在 Service 里面？

因为 Mapper 专门负责数据库访问，
Service 专门负责业务逻辑。

这样职责清晰、降低耦合，也更方便后续维护和修改。


6、@Autowired 是干什么的？
为什么我们现在的代码没有写 @Autowired，也能注入 UserService？

@Autowired 用于依赖注入，让 Spring 自动提供需要的对象。

如果使用单一构造方法进行依赖注入，
Spring 可以自动识别这个构造方法，
因此不需要显式添加 @Autowired。


7、@RestController 是干什么的？

@RestController 用来标识一个 Controller，
告诉 Spring：

“这个类负责接收 HTTP 请求，并返回数据给前端。”


8、@PathVariable 是干什么的？

@PathVariable 用来获取 URL 路径中的参数。

例如：

@GetMapping("/user/{id}")

请求：

/user/100

那么：

@PathVariable Long id

得到：

id = 100


9、@RequestBody 是干什么的？

@RequestBody 用来接收 HTTP 请求 Body 中的 JSON 数据，
并将 JSON 转换成 Java 对象。

例如前端：

{
"name": "张三",
"age": 25
}

↓

@RequestBody User user

↓

User Java 对象
