# 二、Controller

Controller 负责：

> **处理 HTTP 请求。**

例如：

```
@RestController
public class TestController {

    @GetMapping("/hello")
    public String hello() {
        return "Hello Full Stack";
    }
}
```

其中：

```
@RestController
```

告诉 Spring：

> 这个类是用来接收 HTTP 请求的 Controller。

```
@GetMapping("/hello")
```

表示：

> GET /hello 请求进入这个方法。

## Controller 不应该负责大量业务逻辑

Controller 更适合：

```
接收参数
 ↓
调用 Service
 ↓
返回结果
```

而不是：

```
Controller
 ↓
查询数据库
 ↓
验证密码
 ↓
复杂业务判断
 ↓
生成 JWT
 ↓
……
```

# 三、Service

Service 负责：

> **业务逻辑。**

例如登录：

```
Controller
 ↓
收到用户名、密码
 ↓
Service
 ↓
查询用户
 ↓
判断用户
 ↓
验证密码
 ↓
生成 Token
 ↓
返回结果
```

## 为什么不能什么都塞进 Service？

因为：

> **职责太多会导致代码臃肿、难以维护和复用。**

核心思想：

```
职责分离
```

例如：

```
Controller → HTTP
Service    → 业务逻辑
Mapper     → 数据库
```

# 四、Mapper

Mapper 负责：

> **和数据库进行交互。**

项目中：

```

        extends BaseMapper<UserEntity> {
}

继承：

```

```

之后 MyBatis-Plus 提供了很多常用数据库操作。

例如：

```

```

查询 ID 为 1 的用户。

```

## record 怎么理解？

```

}
```

可以简单理解为：

> 定义一个专门装 `token` 的数据对象。

创建对象：

```

```

就是：

> 创建一个 LoginResponse，并把 token 放进去。

如果有多个字段：

```

        Long id,
        String name,
        Integer age
) {
}
```

就是一个装：

```
id
name
age
```

的数据对象。

# 十一、VO

> **View Object，视图对象。**

可以简单理解：

> 专门为了前端展示而准备的数据对象。

# 十四、QueryWrapper

QueryWrapper：

> **用来组装数据库查询条件。**

例如：

```
QueryWrapper<UserEntity> wrapper =
        new QueryWrapper<>();

wrapper.gt("age", 18);
```

对应：

```
WHERE age > 18
```

## 常见条件

```
eq          =
ne          <>
gt          >
ge          >=
lt          <
le          <=
```

例如：

```
wrapper.eq("name", "王五");
```

对应：

```
name = '王五'
```

# 十五、LIKE

```
wrapper.like("name", "王");
```

对应：

```
name LIKE '%王%'
```

表示：

> 包含“王”。

```
wrapper.likeRight("name", "王");
```

对应：

```
name LIKE '王%'
```

表示：

> 以“王”开头。

# 十六、AND / OR

默认多个条件：

```
wrapper.gt("age", 18);
wrapper.eq("name", "王五");
```

相当于：

```
WHERE age > 18
AND name = '王五'
```

OR：

```
wrapper.gt("age", 40);
wrapper.or();
wrapper.eq("name", "王五");
```

相当于：

```
WHERE age > 40
OR name = '王五'
```

复杂条件：

```
wrapper.gt("age", 20);

wrapper.and(w ->
        w.eq("name", "王五")
         .or()
         .eq("name", "李四")
);
```

相当于：

```
WHERE age > 20
AND (name = '王五' OR name = '李四')
```

# 十七、Lambda

例如：

```
w -> w.eq("name", "王五")
```

简单理解：

```
传进来一个 w
 ↓
对 w 调用 eq()
```

`w` 只是变量名。

也可以写：

```
x -> x.eq("name", "王五")
```

# 十九、事务 @Transactional

例如：

```
@Transactional
public void testTransaction() {

    user.setAge(99);

    userMapper.updateById(user);

    throw new RuntimeException("故意制造异常");
}
```

如果发生异常：

```
更新数据库
 ↓
发生异常
 ↓
事务回滚
 ↓
之前的数据库修改撤销
```

核心：

> **事务保证一组数据库操作要么一起成功，要么失败时回滚。**

# 二十二、全局异常处理

使用：

```
@RestControllerAdvice
```

统一处理异常。

例如：

```
@ExceptionHandler(RuntimeException.class)
public Result<Void> handleRuntimeException(
        RuntimeException e) {

    return new Result<>(
            401,
            e.getMessage(),
            null
    );
}
```

作用：

> 不需要每个 Controller 都自己 try-catch，可以集中处理异常。

# 二十三、JWT

JWT 用来：

> **保存登录后的身份信息，让服务器识别用户。**

JWT 基本结构：

```

```

例如：

```

```

## JWT 注意

Payload：

> **不是加密的。**

所以不要把密码等敏感信息直接放进去。

# 二十七、Authorization

请求头：

```
Authorization: Bearer xxx
```

代码：

```
String authorization =
        request.getHeader("Authorization");
```

获取请求头。

然后：

```
String token =
        authorization.substring(7);
```

去掉：

```
Bearer 
```

得到真正的 JWT。

# 二十八、request.setAttribute()

拦截器验证 JWT 后：

```
request.setAttribute(
        "userId",
        userId
);
```

表示：

> 把当前登录用户 ID 暂时放到当前 HTTP 请求里。

Controller：

```

        (String) request.getAttribute("userId");
```

把它取出来。

所以：

```
setAttribute()
       ↓
存

getAttribute()
       ↓
取
```

两者是一对。

# 三十五、找工作面试：目前必须会回答的问题

## 1. Controller 和 Service 的区别？

> Controller 主要负责处理 HTTP 请求，Service 主要负责业务逻辑。

## 2. 为什么使用 Service？

> 为了职责分离，让 Controller 不承担业务逻辑，同时方便代码复用和测试。

## 3. Mapper 是干什么的？

> Mapper 负责和数据库进行交互，执行数据库查询、更新等操作。

## 4. 什么是依赖注入？

> Spring 负责创建和管理对象，并把对象需要的依赖自动注入进去。

## 5. QueryWrapper 是干什么的？

> 用来组装数据库查询条件。

## 6. @RequestBody 是干什么的？

> 把 HTTP 请求体中的 JSON 数据转换成 Java 对象。

## 7. @Valid 是干什么的？

> 对请求对象进行参数校验。

## 8. @Transactional 是干什么的？

> 保证一组数据库操作在事务中执行，发生异常时可以回滚。

## 9. JWT 是什么？

> JWT 是一种用于身份认证的 Token，服务器可以通过验证 JWT 判断请求用户的身份。

## 10. JWT 能不能存密码？

> 不应该。JWT 的 Payload 默认不是加密的，敏感信息不能直接放进去。

## 11. Interceptor 是干什么的？

> 可以在 Controller 执行之前拦截请求，例如统一验证 JWT 登录状态。

## 12. `return true` 和 `return false` 有什么区别？

```
true
 ↓
放行

false
 ↓
拦截
```

## 13. DTO 是什么？

> DTO 是数据传输对象，用来在不同层或系统之间传输数据。

## 14. 为什么不直接返回 Entity？

> 避免把数据库内部字段直接暴露给前端，同时可以根据接口需求控制返回的数据。
